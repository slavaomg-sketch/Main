# Модель безопасности

Принцип: клиент отправляет намерение, сервер принимает решение. Клиент не определяет валюту, награды,
предметы, попадания, круги, чекпоинты, финиш, позицию, разблокировки, характеристики, покупки, цели.

## Слои защиты

1. **Схемы remote** (`NetworkSchemas`): типы, диапазоны, enum, длина строк ≤128, таблицы ≤64 записей,
   глубина ≤4, NaN/inf отвергаются, Instance в аргументах отвергается.
2. **Rate limit**: token bucket на игрока и remote; параметры в схеме.
3. **State gate**: remote принимается только в перечисленных состояниях гонки.
4. **Серверное владение**: предметы выдаются `ItemRoll` на сервере, цель Hunter Wisp выбирается сервером
   (aim клиента — только подсказка в конусе 35°, либо явный выстрел назад), попадания — `ProjectileSim` +
   `HitSystem`, чекпоинты/круги — `CheckpointSystem` по позициям, считанным сервером.
5. **Физическая валидация** (`KartValidationService`, 5 Гц): скорость > cap (учитывая бусты/пады/осколки
   ×1.12 tolerance) → SpeedHack + мягкая коррекция; скачок > 260 studs/s → Teleport; высота > 90 над трассой → Fly;
   угловая скорость > 21 rad/s; вне коридора трассы (2.5 × ширины) → OffCorridor (респавн через 3 с);
   невозможное время сектора (< длина/globalCap × 0.55) → ImpossibleSector, чекпоинт не засчитан.
6. **Suspicion score** (`SecurityService`): веса по причинам, распад 0.5/с, порог 60; kick только при
   ≥3 тяжёлых (вес ≥6) инцидентах за 2 минуты. Одно физическое отклонение никогда не ведёт к kick.
7. **Идемпотентность**: награды по ключу `RaceId:UserId` в профиле, покупки по `purchaseId`, тикеты по id.
8. **Профили**: session lock в записи DataStore, UpdateAsync, retry с backoff, temporary-профиль при ошибке
   загрузки (покупки запрещены, default никогда не пишется поверх реального).

## Проверенные сценарии (tests/Security/Exploits.spec.luau)

Использование отсутствующего предмета; 100 использований/с; поддельная цель; телепорт на километр;
финиш без чекпоинтов; NaN/inf/неверные типы/Instance; чужой транспорт и завышенный tier дрифта;
отсутствие remote для валюты/наград; speed/fly/spin проверки; политика kick; валидация правил комнаты.
Все сценарии завершаются безопасным отказом.
