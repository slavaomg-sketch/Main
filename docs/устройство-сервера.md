## Выкладка

Обновление запускается **сигнальным файлом**, а не командой:

```
touch ~/dashboard-deploy/request
```

Дальше системная служба от root выполняет `/usr/local/sbin/marketplace-dashboard-update`:
забирает ветку, ставит зависимости, **прогоняет тесты**, сохраняет предыдущую
версию, копирует код, перезапускает службу и проверяет, что панель отвечает.
Если тесты упали или панель не поднялась — откат к прежней версии.

Журнал последней выкладки: `~/dashboard-deploy/last-update.log`.

**Ветка в этом скрипте зашита:** `claude/marketplace-unified-dashboard-anbqou`.
Сервер выкладывает только её. Работа в другой ветке до сервера не доедет,
пока владелец не поправит скрипт с правами root.

Привилегированная часть лежит в `/usr/local/sbin` и кодом панели не
перезаписывается. Это сделано намеренно: изменить её, просто отправив
коммит, невозможно.

## Почему панель многого «не видит»

Служба панели ужата настройками systemd: `ProtectHome=true` (домашние
каталоги невидимы), `ProtectSystem=strict` (файловая система только на
чтение), `NoNewPrivileges=true`. Писать она может только туда, что
перечислено в `ReadWritePaths`.

Отсюда следствие: чтобы дать панели новый каталог, мало прав на сам
каталог — нужно ещё разрешение в службе. Это разово делает
`deploy/codex-bridge-allow.sh` с `sudo`.

## Мост к Codex CLI

Панель и Codex работают от разных пользователей, и панель не может
запустить Codex напрямую. Между ними — каталог-почтовый ящик:

```
/var/lib/wb-agent/queue     панель кладёт задание
/var/lib/wb-agent/answers   мост кладёт ответ
/var/lib/wb-agent/work      рабочий каталог Codex (пустой)
```

Мост — служба пользователя `codex-bridge` (`systemctl --user`), работает от
того же пользователя, под которым авторизован Codex. Root ей не нужен:
автозапуск обеспечивает `loginctl enable-linger`.

Полезное:

```
systemctl --user status codex-bridge      # состояние моста
tail -20 /var/lib/wb-agent/worker.log     # что он делал
curl -s .../api/health                    # поле agent — видит ли панель мост
```

Установка с нуля — два шага, первый разово с root:

```
sudo bash deploy/codex-bridge-allow.sh    # каталог и разрешение службе
bash deploy/codex-bridge-install.sh       # сам мост и его служба
```

## Диагностика без доступа к базе

База принадлежит `mpdashboard` и посторонним не читается, а `sudo` из-под
рабочего окружения заблокирован флагом `no_new_privileges`. Поэтому
диагностика делается через журнал службы:

```
journalctl -u marketplace-dashboard --since "10 min ago" --no-pager | tail -40
python -m dashboard.diagnose             # структура ответа площадки, ключи замаскированы
python -m dashboard.reconcile            # сверка источников, пишет в журнал
```
