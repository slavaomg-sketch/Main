# Архитектура TechMatch

## Обзор

TechMatch — модульный монолит на TypeScript: одно приложение Next.js (витрина + админка + API), один фоновый воркер, PostgreSQL как единственный источник истины, Redis для очередей. Доменная логика вынесена в отдельные пакеты и не зависит от React.

```
apps/
  web/        Next.js 16 (App Router): storefront, /admin, route handlers, server actions
  worker/     BullMQ-воркер: истечение резервов, пересчёт совместимости, синхронизация маркетплейсов
packages/
  config/     валидация переменных окружения (zod), статус интеграций
  database/   Prisma-схема, миграции, клиент, seed и демо-изображения
  domain/     доменные модули и сервисы (см. ниже)
  integrations/ адаптеры внешних систем: платежи, доставка, уведомления, чеки, импорт файлов, маркетплейсы, LLM
  validation/ общие zod-схемы форм
  testing/    утилиты интеграционных тестов (тестовая БД, фикстуры)
  ui/         design tokens (tokens.css)
docs/         архитектура, модель данных, движок совместимости, импорт, деплой, ограничения
legacy/reminder-bot/  прежнее содержимое репозитория (Telegram-бот), перенесено без изменений
```

## ADR-001. Стек и границы

- **Next.js 16 + React 19** — SSR публичных страниц (SEO), server actions для форм, route handlers для webhook/экспорта. Все страницы каталога рендерятся на сервере; клиентские компоненты — только интерактив (поиск с подсказками, корзина, формы).
- **Prisma 6 + PostgreSQL 16** — выбран Prisma 6 (stable), а не 8-rc: предсказуемые миграции и driver-less клиент. pg_trgm + full-text search покрывают поиск без внешнего кластера; `SearchProvider` оставлен для перехода на Meilisearch/OpenSearch.
- **Деньги — целые копейки (`Int`)**. Никаких float в расчётах (`packages/domain/src/pricing`).
- **Модульный монолит**: React-компоненты не обращаются к Prisma напрямую — только через сервисы `@techmatch/domain`. Исключение — простые чтения справочников в серверных страницах и админке через `prisma` там, где сервис был бы бесполезной обёрткой; запись всегда идёт через сервисы/actions с аудитом.
- **Интеграции — только через интерфейсы** (`PaymentProvider`, `DeliveryProvider`, `NotificationProvider`, `FiscalReceiptProvider`, `MarketplaceAdapter`, `ImportFileAdapter`, `LlmAssistant`). Без ключей фабрика возвращает явный mock и `describeProviders()` показывает режим в админке и `/api/health`.
- **Совместимость — доменная модель**, а не текст в карточке: характеристики устройств и товаров + правила + явные связи + override. Вердикт всегда считается на сервере (`packages/domain/src/compatibility`).
- **Бот напоминаний** из исходного репозитория перенесён в `legacy/reminder-bot/` целиком: он не связан с магазином, но удалять чужой рабочий код без причины нельзя. Его скрипты используют относительные пути и продолжают работать из новой папки.

## Доменные модули (`packages/domain/src`)

| Модуль | Ответственность |
|---|---|
| `shared` | деньги, slug/транслитерация, нормализация запросов, ошибки, пароли (scrypt), id |
| `compatibility` | типы, правила, движок, профили из БД, сервис (кеш, persist, override, evidence) |
| `devices` | поиск устройств (алиасы, идентификаторы, триграммы, разрешение неоднозначности), категории |
| `search` | `SearchProvider` (PostgreSQL), подсказки устройств + товаров |
| `catalog` | список товаров с фильтрами/фасетами/сортировкой/совместимостью, страница товара, бренды, категории |
| `pricing` | итоги корзины, скидки, комплекты |
| `inventory` | резервирование `FOR UPDATE`, списание, освобождение, просрочка |
| `cart` | корзина гостя/пользователя, слияние, промокоды, скидки за комплекты |
| `checkout` | транзакционное создание заказа, идемпотентность, доставка, платёж |
| `orders` | конечный автомат статусов, история, отмена, возвраты, отправления |
| `payments` | идемпотентная обработка webhook, повторная оплата, чеки |
| `customers` | регистрация/вход/сессии, «Мои устройства», избранное, адреса |
| `promotions` | купоны, акции, комплекты |
| `content` | настройки главной, баннеры, подборки, страницы, FAQ, подписка |
| `imports` | конвейер импорта, ownership полей, экспорт CSV/XLSX/YML |
| `media` | хранение изображений, дедупликация sha256, варианты размеров (sharp), S3-заготовка |
| `notifications` | письма о заказе через провайдера |

| `audit` | журнал изменений с маскированием секретов |
| `maintenance` | фоновые задачи (воркер или inline) |

## Потоки данных

**Подбор**: ввод → `/api/search/suggest` (debounce 180 мс) → `searchDevices` (нормализация → алиасы → идентификаторы → триграммы) → `exact | ambiguous | none` → `/device/[slug]` → `evaluateDeviceCatalog` (все активные товары × профиль устройства, кеш 60 с, persist в `CompatibilityRelation` source=RULE) → категории и карточки со статусом.

**Заказ**: корзина (cookie `tm_cart`, подписанной сессией) → `createOrderFromCart`: ключ идемпотентности → котировка доставки → транзакция (заказ + позиции + `reserveStock` с `SELECT … FOR UPDATE` + купон) → платёж у провайдера → письмо. Оплата подтверждается только webhook (`PaymentEvent` уникален по `providerEventId`) → `transitionOrder(PAID)` → списание резерва → чек.

**Импорт**: файл → `ImportJob` (анализ, hash) → mapping → dry-run (`ImportRow.action`, diff, issues) → подтверждение → `applyImport` (upsert `ExternalListing`, ownership полей) → журнал.

## Безопасность

Серверная валидация (zod) во всех actions; сессии — случайный токен, в БД хранится sha256; cookies `httpOnly` + `sameSite=lax` + `secure` в production; RBAC через `requirePermission`; edge-`proxy.ts` закрывает `/admin` без cookie; rate limiting на входе/регистрации/подписке/checkout/webhook (счётчики в PostgreSQL, без Redis); webhook — подпись HMAC (mock) или проверка IP + повторный запрос статуса (ЮKassa); идемпотентность заказов и событий оплаты; аудит с маскированием полей `password|secret|token|key`; загрузка изображений с проверкой MIME через sharp и лимитом размера; секретов в репозитории нет (`.env.example`).

## Масштабирование

Пересчёт совместимости для всех устройств выполняется воркером раз в час и по событию; страницы устройств отдаются из кеша процесса (60 с). При росте каталога следующий шаг — материализованная выборка `CompatibilityRelation` вместо оценки «на лету» и `SearchProvider` на внешнем движке.
