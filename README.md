# Панель маркетплейсов

Одна веб-страница, на которой видно всё: Wildberries, Ozon, Яндекс Маркет и
AliExpress в общих цифрах и по отдельности. Панель собирается из блоков —
их можно **добавлять, удалять, менять местами, менять размер и скрывать**,
и раскладка запоминается.

```
    ВЫРУЧКА          ПРИБЫЛЬ          ЗАКАЗЫ           СРЕДНИЙ ЧЕК
    20,5 млн ₽       4,9 млн ₽        7 283            2 809 ₽
    ▼ 4,8%           ▼ 4,6%           ▼ 5,0%           ▲ 0,3%

    ДИНАМИКА ВЫРУЧКИ ─────────────────────────────────────────────
    все площадки · Wildberries · Ozon · Яндекс Маркет · AliExpress

    ДОЛИ ПЛОЩАДОК          ЮНИТ-ЭКОНОМИКА
    WB 40% · Ozon 35%      себестоимость · комиссия · логистика · реклама
```

Это обычный сайт: открывается в браузере на компьютере, планшете и телефоне.
Телеграм для неё не нужен — бот напоминаний в этом же репозитории живёт
отдельно и панели никак не касается.

---

## Что показывает

**Деньги**

- Выручка, прибыль, средний чек, маржинальность — с динамикой к прошлому
  сопоставимому периоду.
- Юнит-экономика: из чего складывается прибыль — себестоимость, комиссия
  площадки, логистика, реклама.
- ДРР — доля рекламных расходов в выручке.
- План продаж: сколько прошли от месячной цели.

**Продажи**

- График выручки по дням: общая линия и линия каждой площадки.
- Заказы по дням, доли площадок, география продаж по регионам.
- Сравнение площадок в одной таблице: выручка, доля, заказы, чек, выкуп,
  возвраты, ДРР, прибыль.
- Сравнение **магазинов**: каждый кабинет отдельной строкой — какой из двух
  Wildberries приносит больше.
- Топ товаров по выручке с остатками.

**Операции**

- Заканчивающиеся остатки: на сколько дней хватит запаса, по складам.
- Воронка: показы → карточка → корзина → заказ → выкуп, с конверсиями.
- Последние отзывы и средний рейтинг.
- Статус подключений: какая площадка отдаёт данные, а какая нет.

Всего 21 тип блоков. Любой можно поставить в нескольких экземплярах.

## Как настраивается под себя

1. **Настроить** в шапке — панель переходит в режим сборки.
2. **Перетащите** блок мышью или пальцем в нужное место.
3. **S / M / L / XL** — ширина блока: от четверти строки до всей строки.
4. **Глаз** — скрыть блок, не удаляя (пригодится для сезонных отчётов).
5. **×** — удалить блок.
6. **Добавить блок** — библиотека всех доступных блоков с описаниями.
7. **Новая вкладка** — вторая, третья раскладка: например, «Ежедневная»,
   «Финансы», «Склад». Переключаются в шапке, у каждой свой набор блоков.

Раскладка сохраняется на сервере — она одинаковая на компьютере в офисе
и на телефоне. `Готово` завершает настройку, `Сбросить` возвращает
стандартный набор блоков.

Сверху выбираются **период** и **площадки**. Периоды: сегодня, вчера,
7 и 30 дней, а также календарные — месяц, квартал, полугодие, год — и свой
диапазон. Площадки можно включать по одной: смотреть только Wildberries
или только Ozon и Яндекс вместе.

Оформление подстраивается под систему: светлая и тёмная тема, кнопка
в шапке переключает вручную. Данные обновляются сами раз в пять минут.

## Быстрый старт

### Посмотреть у себя на компьютере

```bash
make install
make dashboard
```

Откройте <http://localhost:8080>. Без ключей маркетплейсов панель показывает
**демонстрационные данные** — можно сразу посмотреть, как всё выглядит,
и собрать свою раскладку.

### Развернуть на VPS

Один раз на сервере (Ubuntu 22.04/24.04 или Debian 11/12):

```bash
sudo apt update && sudo apt install -y git
git clone https://github.com/slavaomg-sketch/Main.git ~/dashboard-src
cd ~/dashboard-src
sudo bash deploy/dashboard-install.sh
```

Установщик поставит Python и зависимости, создаст отдельного пользователя
`mpdashboard`, спросит пароль для входа, настроит автозапуск и покажет адрес
вида `http://ВАШ_СЕРВЕР:8080`. Повторный запуск скрипта безопасен — он
обновляет код, не трогая настройки и раскладки.

```bash
cp .env.example .env && nano .env
docker compose up -d --build
docker compose logs -f dashboard
```
</details>

### Подключить настоящие данные

Нажмите **значок ключа** в шапке панели — откроется страница «Ключи».
Ничего в файлах править не нужно: вставили ключ, нажали «Сохранить», и панель
сразу начинает показывать ваши продажи. Перезапуск не требуется.

**У площадки может быть несколько магазинов.** Два кабинета на Wildberries,
два на Ozon, по одному на Яндексе и AliExpress — добавьте каждый кнопкой
«Ещё один магазин», дайте ему понятное название, и в отчётах он будет виден
и отдельной строкой, и в общей сумме. Магазин можно временно выключить —
тогда он не опрашивается и в цифры не попадает.

| Площадка | Где взять ключ |
|---|---|
| Wildberries | Личный кабинет → Настройки → Доступ к API, категории **«Статистика» и «Аналитика»** |
| Ozon | Seller → Настройки → API-ключи (`Client-Id` и `Api-Key`) |
| Яндекс Маркет | Кабинет продавца → Настройки → API (`Api-Key` и номер кампании) |
| AliExpress | Open Platform: `openservice.aliexpress.com` |

У Wildberries нужны **обе категории**: продажи и заказы отдаёт «Статистика»,
а остатки с июня живут в «Аналитике» (старый метод `supplier/stocks` отключён).
Если в токене только «Статистика», панель покажет продажи и заказы, а рядом —
пометку «частично» с пояснением, чего не хватает.

Рядом с каждым магазином есть кнопка **«Проверить связь»**: она делает
настоящие запросы к площадке и показывает, что та ответила — код ответа,
сколько строк пришло и какие в них поля. Сразу видно, живой ключ или нет.

Как ключи хранятся:

- в базе панели, **зашифрованными** (Fernet, ключ выводится из `DASHBOARD_SECRET`);
- обратно в браузер не отдаются — приходят только последние четыре символа;
- файл базы создаётся с правами `600`, читать его может только владелец;
- в лог и в интерфейс ключ не попадает, даже если площадка вернула его
  внутри текста ошибки.

Поэтому задайте свой `DASHBOARD_SECRET` и `DASHBOARD_PASSWORD` — панель
сама предупредит на странице «Ключи», если этого не сделать.

Старый способ тоже работает: ключи, прописанные в `.env`, показываются
на странице отдельной строкой с пометкой «из .env» и правятся только
на сервере.

```bash
sudo nano /opt/marketplace-dashboard/.env
sudo systemctl restart marketplace-dashboard
```

### Проверить, что ключи работают

```bash
make diagnose                             # все площадки за 30 дней
make diagnose ARGS="--days 7"             # короткий период
python -m dashboard.diagnose --marketplace ozon
```

То же, что кнопка «Проверить связь», но для всех магазинов сразу и в консоли.
Печатает только **структуру** ответа — код, число строк, имена полей и форму
значений: дата показывается как `9999-99-99`, название товара как `xxxxxxxx`,
сумма как `число`.

```
Wildberries — магазин 1  (Wildberries, введён в панели)
    ключи: token=••••c3d4
    GET /api/v1/supplier/sales   →  200 · строк: 1420
        date: «9999-99-99x99:99:99»
        finishedPrice: число
        supplierArticle: «xxx-999-xx»
    GET /api/v1/supplier/stocks  →  ОШИБКА 401
        unauthorized: token ••••c3d4 has no 'stocks' scope
    разбор ответа: точек графика 7, товаров 20, выручка посчитана
```

Ключи в выводе замаскированы — в том числе если площадка вернула ключ
внутри текста ошибки. Ни сумм, ни названий товаров в отчёте нет, поэтому
его можно переслать тому, кто помогает с настройкой. Если нужны настоящие
значения — добавьте `--values`, но такой вывод уже никому не показывайте.

**Не пересылайте сами ключи в переписке.** Wildberries позволяет выпустить
токен только с категорией «Статистика», Яндекс Маркет — ключ с ограниченными
правами; у Ozon и AliExpress ключ по умолчанию даёт и право записи, то есть
возможность менять цены и остатки. Для настройки интеграции ключи не нужны —
достаточно отчёта выше.

## Настройки панели (`.env`)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `DASHBOARD_PASSWORD` | пусто | Пароль входа. Пусто — панель открыта всем, у кого есть адрес |
| `DASHBOARD_SECRET` | — | Секрет подписи cookie, генерируется установщиком |
| `DASHBOARD_HOST` | `0.0.0.0` | Адрес, на котором слушать |
| `DASHBOARD_PORT` | `8080` | Порт |
| `DASHBOARD_DB_PATH` | `data/dashboard.db` | Файл с раскладками |
| `DASHBOARD_CACHE_TTL` | `300` | Сколько секунд держать посчитанный отчёт в памяти |
| `DASHBOARD_SYNC_MINUTES` | `15` | Как часто обновлять выгрузку с площадок |
| `DASHBOARD_HISTORY_DAYS` | `400` | Сколько дней истории хранить на сервере (нужно для периода «Год») |
| `DASHBOARD_HTTP_TIMEOUT` | `30` | Таймаут запроса к API маркетплейса |
| `DASHBOARD_DEMO` | `0` | `1` — показывать демо-данные, даже если ключи заданы |
| `WB_API_TOKEN` | пусто | Wildberries (можно вместо этого ввести на странице «Ключи») |
| `OZON_CLIENT_ID`, `OZON_API_KEY` | пусто | Ozon |
| `YANDEX_API_KEY`, `YANDEX_CAMPAIGN_ID`, `YANDEX_BUSINESS_ID` | пусто | Яндекс Маркет |
| `ALI_APP_KEY`, `ALI_APP_SECRET`, `ALI_ACCESS_TOKEN` | пусто | AliExpress |

## Как это устроено

```
dashboard/
├── main.py            запуск веб-сервера, отдача страницы
├── api.py             HTTP API: данные, раскладки, вход
├── config.py          чтение .env и ключей площадок
├── models.py          единая модель данных для всех маркетплейсов
├── aggregator.py      параллельный опрос площадок, свод, кэш
├── blocks.py          каталог блоков и проверка раскладки
├── db.py              хранение раскладок (SQLite)
├── connections.py     магазины и их ключи: шифрование, несколько на площадку
├── warehouse.py       выгрузка площадок в свою базу и чтение из неё
├── security.py        вход по паролю
├── diagnose.py        проверка ключей: что именно отдаёт API площадки
└── connectors/
    ├── base.py        общий контракт: fetch(период) → отчёт
    ├── dates.py       разбор дат в форматах разных площадок
    ├── wildberries.py Statistics API
    ├── ozon.py        Seller API
    ├── yandex.py      Partner API
    ├── ali.py         Open Platform с подписью запроса
    └── demo.py        правдоподобные данные, пока нет ключей

web/
├── index.html         разметка страницы
├── css/app.css        оформление, светлая и тёмная тема
└── js/
    ├── app.js         состояние, режим настройки, перетаскивание
    ├── blocks.js      отрисовка каждого типа блока
    ├── charts.js      графики на чистом SVG
    ├── api.js         обращения к серверу
    └── format.js      форматирование чисел и дат
```

**Ключевые решения**

- **Магазин, а не площадка.** Ключи привязаны к магазину: у Wildberries их
  может быть два, у Ozon два, у Яндекса один. Магазины опрашиваются
  параллельно и сводятся в одну строку площадки, но разбивка сохраняется.
- **Единая модель данных.** Каждый маркетплейс говорит на своём языке:
  у WB «продажи» и `forPay`, у Ozon метрики массивом по позициям, у Яндекса
  заказы постранично, у AliExpress подписанный запрос. Коннектор приводит
  всё к одному виду — дальше по коду разницы между площадками нет.
- **Падение площадки не гасит панель.** Ошибка сети или ключей превращается
  в отчёт с пометкой «ошибка»: остальные площадки показываются как обычно.
- **Частичный ответ лучше пустого.** Если Wildberries отдал заказы, но не отдал
  остатки, отчёт покажет заказы и отдельно скажет, чего не хватает. Одна упавшая
  ручка не обнуляет площадку целиком.
- **Лимиты площадок соблюдаются.** У статистики Wildberries — примерно один
  запрос в минуту на метод. Панель считает текущий период и прошлый, поэтому
  сначала запрашивает более широкий диапазон и переиспользует ответ: обращение
  к площадке одно вместо двух. Если лимит всё же сработал, панель ждёт ровно
  столько, сколько просит площадка, и не дольше десяти секунд.
- **Площадки опрашиваются параллельно**, одна медленная не задерживает остальные.
- **Данные выгружаются на сервер, а не тянутся при каждом клике.** Раз в
  15 минут панель дозагружает сырые строки площадки и складывает в свою базу;
  первая выгрузка берёт всю историю, последующие — только изменения за
  последние дни, поэтому год продаж не перекачивается каждые четверть часа;
  отчёт за любой период считается уже из неё. Переключение периодов —
  мгновенное, лимиты маркетплейсов не расходуются, и панель продолжает
  показывать цифры, даже если площадка недоступна. Хранятся именно сырые
  строки: логику отчёта можно менять без повторной выгрузки.
- **Демо-режим по умолчанию.** Панель запускается и выглядит законченной
  до того, как получены ключи. Данные детерминированы — графики не «прыгают»
  при обновлении страницы.
- **Раскладка проверяется на сервере.** В базу попадают только известные типы
  блоков и допустимые размеры, а не произвольный JSON из браузера.
- **Никаких внешних библиотек на фронтенде.** Графики нарисованы на SVG
  вручную: нечего собирать, нечему устареть, страница открывается мгновенно.

## Тесты

```bash
make test     # 307 тестов, из них 229 — про панель
make lint
```

Проверяются: расчёт показателей и периодов, свод по площадкам и сравнение
с прошлым периодом, разбор ответов каждого маркетплейса (включая форматы
дат и подпись AliExpress), устойчивость к сбоям площадки, весь HTTP API,
сохранение раскладок, вход по паролю, шифрование ключей, сведение отчётов
нескольких магазинов и то, что ключи не утекают ни в лог, ни в интерфейс,
ни в ответ API, ни в отчёт диагностики.

## Обновление без терминала

Обычно обновление — это `sudo bash deploy/dashboard-install.sh`. Если вводить
команды каждый раз не хочется, можно настроить обновление по сигналу — один
раз:

```bash
sudo bash ~/dashboard-src/deploy/enable-selfupdate.sh
```

После этого обновление запускается созданием файла, без прав администратора:

```bash
touch ~/dashboard-deploy/request
cat ~/dashboard-deploy/last-update.log   # что получилось
```

Что делает обновление: забирает свежий код ветки, ставит зависимости,
**прогоняет тесты** и выкладывает только если они прошли, сохраняет
предыдущую версию, перезапускает службу и проверяет, что панель отвечает.
Если не отвечает — откатывается на предыдущую версию сам.

Привилегированный скрипт лежит в `/usr/local/sbin` и обновлением **не
перезаписывается**, поэтому изменить его, отправив коммит, нельзя:
выкладываемый код работает от непривилегированного пользователя `mpdashboard`.

Выключить:

```bash
sudo systemctl disable --now marketplace-dashboard-update.path
```

## Эксплуатация сервера

| Задача | Команда |
|---|---|
| Состояние | `sudo systemctl status marketplace-dashboard` |
| Логи в реальном времени | `sudo journalctl -u marketplace-dashboard -f` |
| Перезапуск | `sudo systemctl restart marketplace-dashboard` |
| Изменить настройки | `sudo nano /opt/marketplace-dashboard/.env` затем перезапуск |

**Что где лежит**

```
/opt/marketplace-dashboard/
├── dashboard/            код сервера
├── web/                  страница
├── .venv/                зависимости
├── .env                  пароль, секрет и (необязательно) ключи площадок, права 600
└── data/dashboard.db     раскладки, зашифрованные ключи и выгрузка продаж, права 600
```

**Безопасность.** Панель работает от системного пользователя без права входа,
systemd закрывает ей доступ к остальной файловой системе. Ключи маркетплейсов
в браузер не передаются — запросы к API площадок делает только сервер.
Введённые через панель ключи лежат в базе зашифрованными, прописанные
вручную — в `.env` с правами `600`.

Если панель смотрит в интернет, задайте `DASHBOARD_PASSWORD`. Для работы
по `https` поставьте перед панелью nginx с сертификатом Let's Encrypt —
панель слушает обычный HTTP на `127.0.0.1`, если поменять `DASHBOARD_HOST`.

# Бот напоминаний для сотрудников

> Вторая, независимая часть репозитория. Панели маркетплейсов бот не нужен —
> если вам нужна только панель, всё, что ниже, можно не читать.

Телеграм-бот, который присылает сотрудникам напоминания о рабочих процессах
в удобное **им** время, собирает отметки о выполнении и вечером отправляет
руководителю сводный отчёт.

```
09:00  🔔 Открытие смены       →  сотрудник ставит галочки
13:00  🔔 Обход зала           →  ✅ ✅ ◻️  💬 «склад закрыт, ключи у Сергея»
20:00  📊 Отчёт руководителю   →  кто что сделал, что забыл и почему
```

---

## Что умеет

**Сотрудник**

- Получает напоминания в назначенное время — **время выбирает сам** под свой график.
- Отмечает выполнение галочками по пунктам чек-листа, затем жмёт «Готово».
- Может нажать «Не смогу» — бот спросит причину, она уйдёт в отчёт.
- Может дописать **комментарий** к любому напоминанию: почему пункт не сделан,
  что помешало, что стоит знать руководителю. Комментарий доступен и после
  закрытия напоминания.
- Создаёт **личные** напоминания со своим чек-листом.
- Указывает свой часовой пояс (важно для филиалов в разных регионах).
- Смотрит собственную статистику за неделю.

**Руководитель**

- Создаёт **общие** напоминания — обязательные подключаются всем сотрудникам автоматически.
- Задаёт чек-лист: что именно должно быть сделано.
- Видит список сотрудников, отключает уволенных.
- Получает **вечерний отчёт** — автоматически, в заданное время,
  с невыполненными пунктами и пояснениями сотрудников.
- Может запросить отчёт за любой день командой `/report`.
- Может разослать объявление всем: `/broadcast текст`.

**Автоматика**

- Если сотрудник не отметился — через час приходит повторный «толчок».
- Всё, что не отмечено к вечеру, попадает в отчёт как «не отмечено».
- Если бот перезапускали — напоминание всё равно уйдёт (окно догона 15 минут).
- Повторной отправки одного напоминания за день не происходит никогда.

## Быстрый старт

### 1. Создать бота

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Придумайте имя и адрес бота, скопируйте **токен**.
3. Узнайте свой Telegram ID у [@userinfobot](https://t.me/userinfobot).

### 2. Развернуть на VPS

Один раз на сервере (Ubuntu 22.04/24.04 или Debian 11/12):

```bash
sudo apt update && sudo apt install -y git
git clone https://github.com/slavaomg-sketch/Main.git ~/reminder-bot-src
cd ~/reminder-bot-src
sudo bash deploy/install.sh
```

Установщик сам поставит Python и зависимости, создаст отдельного
пользователя `reminderbot`, спросит токен и ваш Telegram ID, настроит
автозапуск и ежедневный бэкап. Повторный запуск скрипта безопасен —
он обновляет код, не трогая базу и настройки.

Порты открывать не нужно: бот сам ходит в Telegram (long polling),
входящих соединений не принимает.

### 3. Первый запуск

1. Откройте своего бота в Telegram → `/start`. Вы увидите кнопку **🛠 Админка**.
2. **Админка → ➕ Создать напоминание** — задайте название, чек-лист, время и дни.
3. Отправьте сотрудникам ссылку на бота. После их `/start` обязательные
   напоминания подключатся автоматически.
4. Вечером в заданное время вам придёт отчёт.

## Настройки (`.env`)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `BOT_TOKEN` | — | **Обязательно.** Токен от @BotFather |
| `ADMIN_IDS` | — | **Обязательно.** ID руководителей через запятую |
| `DB_PATH` | `data/bot.db` | Файл базы данных |
| `DEFAULT_TZ` | `Europe/Moscow` | Часовой пояс новых сотрудников |
| `REPORT_TIME` | `20:00` | Когда присылать вечерний отчёт |
| `NUDGE_AFTER_MINUTES` | `60` | Через сколько напомнить повторно; `0` — выключить |
| `CATCHUP_MINUTES` | `15` | Окно догона после простоя бота |

## Как это устроено

```
bot/
├── main.py          точка входа: бот, планировщик, polling
├── config.py        чтение .env
├── db.py            схема SQLite
├── repo.py          весь доступ к данным
├── scheduler.py     проверка раз в минуту: что отправить, кого подтолкнуть, когда отчёт
├── reports.py       сборка текста отчётов
├── messages.py      шаблоны сообщений
├── keyboards.py     клавиатуры
├── callbacks.py     фабрики callback_data
├── middlewares.py   регистрация пользователя
└── handlers/
    ├── common.py    старт, меню, настройки
    ├── employee.py  мои напоминания, каталог, создание личного
    ├── admin.py     админка, сотрудники, отчёты
    └── checklist.py галочки в присланном напоминании
```

**Ключевые решения**

- **Проверка раз в минуту, а не задача на каждое напоминание.** Расписание можно
  менять на лету, перезапуск бота ничего не ломает, переход на летнее время
  обрабатывается автоматически.
- **Время считается в часовом поясе сотрудника.** Филиалы в разных регионах
  получают напоминания по своему местному времени.
- **Уникальный ключ `(подписка, дата, время)`** в таблице отправок — техническая
  гарантия, что одно напоминание не придёт дважды за день.
- **Чек-лист копируется в момент отправки.** Если руководитель поменяет пункты
  завтра, вчерашний отчёт останется достоверным.
- **Удаление напоминания мягкое.** История выполнения и старые отчёты сохраняются.
- **Схема обновляется сама.** Новые столбцы доезжают до работающей базы при
  запуске — обновление бота не требует ручных действий с SQL.

## Тесты

```bash
make test     # 78 тестов: время, подписки, статусы, планировщик, отчёты, клавиатуры
make lint
```

Тесты гоняют планировщик на подставном Telegram — проверяется, что напоминание
уходит вовремя, ровно один раз, не уходит в неподходящий день и не уходит
отключённому сотруднику.

## Эксплуатация сервера

| Задача | Команда |
|---|---|
| Состояние | `sudo systemctl status reminder-bot` |
| Логи в реальном времени | `sudo journalctl -u reminder-bot -f` |
| Логи за сегодня | `sudo journalctl -u reminder-bot --since today` |
| Перезапуск | `sudo systemctl restart reminder-bot` |
| Остановить | `sudo systemctl stop reminder-bot` |
| Обновить до свежей версии | `sudo bash ~/reminder-bot-src/deploy/update.sh` |
| Бэкап прямо сейчас | `sudo -u reminderbot bash /opt/reminder-bot/deploy/backup.sh` |
| Восстановить из копии | `sudo bash /opt/reminder-bot/deploy/restore.sh` |
| Изменить настройки | `sudo nano /opt/reminder-bot/.env` затем перезапуск |
| Удалить бота | `sudo bash /opt/reminder-bot/deploy/uninstall.sh` |

**Что где лежит**

```
/opt/reminder-bot/
├── bot/          код
├── .venv/        зависимости
├── .env          токен и настройки (права 600, читает только reminderbot)
├── data/bot.db   вся база: сотрудники, напоминания, отметки, комментарии
└── backups/      копии базы за последние 30 дней
```

**Резервные копии** создаются автоматически каждую ночь в 03:30 таймером
systemd (`sudo systemctl list-timers reminder-bot*`) и хранятся 30 дней.
Копия снимается штатным механизмом SQLite, поэтому остаётся целостной
даже если в этот момент кто-то отмечает галочки.

Скачать копию к себе на компьютер:

```bash
scp root@ВАШ_СЕРВЕР:/opt/reminder-bot/backups/*.gz .
```

**Безопасность.** Бот работает от системного пользователя без права входа,
systemd-юнит закрывает ему доступ к остальной файловой системе (`ProtectSystem=strict`),
писать он может только в свою папку `data/`.

**Если бот не отвечает**

```bash
sudo systemctl status reminder-bot        # запущен ли
sudo journalctl -u reminder-bot -n 50     # последние 50 строк лога
```

Чаще всего причина — опечатка в токене (`Telegram отклонил токен` в логе)
или сервер без интернета (`Нет связи с Telegram`).
