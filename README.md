# ИНФОТРОН

Головоломка в духе **Supaplex**: Мёрфи прогрызает грунт, собирает инфотроны и уходит
в шлюз — пока сверху не прилетел зонк, а из-за угла не вышел патруль.

Чистый HTML + JavaScript: ни зависимостей, ни сборки, ни картинок — вся графика
рисуется кодом. Просто открой `index.html` в браузере.

```
git clone <репозиторий> && cd Main
xdg-open index.html          # или просто открой файл в браузере
```

Одна и та же страница работает и на компьютере, и на телефоне: раскладка,
масштаб поля и способ управления подстраиваются под экран.

## Управление

| Компьютер | Действие |
|---|---|
| Стрелки / WASD | идти (и толкать зонк вбок) — если героев двое, идут оба |
| **Space + направление** | «снап»: выесть клетку, не сходя с места |
| **Backspace (или Z)** | отмотать время назад — держи, чтобы отматывать дальше |
| **H** | совет по нынешнему положению |
| R | начать уровень заново |
| **🔊 в шапке** | звук: включить или выключить |
| Esc / P | пауза и список уровней |

| Телефон | Действие |
|---|---|
| вести пальцем по полю | Мёрфи идёт в ту сторону, пока палец не отпущен |
| крестовина внизу | точные одиночные шаги |
| **СНАП + направление** | выесть клетку, не сходя с места |
| **↶ в шапке** | отмотать время назад — держи палец |
| **? в шапке** | совет по нынешнему положению |
| **🔊 в шапке** | звук: включить или выключить |

Погибнуть здесь не значит начать заново: движок детерминированный, поэтому
время отматывается назад по одному такту. Кнопка «Отмотать назад» в окне
гибели возвращает за черту ошибки, а зажатый Backspace прокручивает ленту
дальше. Уровни, пройденные вообще без отмотки, помечены в списке звёздочкой.

### Советчик

Подсказка считается не от начала уровня, а от того положения, в котором ты
сейчас стоишь, — потому и умеет то, чего обычная подсказка не умеет. Слоёв
три, и каждый честно знает, насколько он уверен.

**Доказанно смертельные ходы** (красные кресты на поле). Для каждого хода
советчик ищет, есть ли хоть какое-то продолжение, при котором Мёрфи проживёт
ещё четырнадцать тактов. Нет ни одного — значит ход смертелен при любой
дальнейшей игре, и это не мнение. Слой работает ровно там, где нужен: на
жучиных уровнях такие ходы находятся на 69% тактов, на уровнях с обходчиками
— на 60%, на спокойных — на 3%.

**Приговор «отсюда уже не пройти».** Считается, до чего Мёрфи вообще может
добраться, нарочно завышая его возможности: сквозь грунт, валуны и заряды.
Если даже при таких поблажках инфотронов не хватает на норму или выход
недостижим — уровень проигран, и это доказано. Оговорка: именно из-за
щедрости оценки приговор срабатывает редко — на гравитационных уровнях
примерно в 4% испорченных положений, на прочих почти никогда. Зато он не
может соврать, и это проверяется на всех уровнях сразу.

**Совет куда идти** (зелёная рамка) — а вот это уже догадка: ближайшая
невзятая добыча по карте. Советчик не выдаёт её за истину. На уровнях вдвоём
он её не даёт вовсе: ход ведёт обоих сразу, и «ближе к добыче» для одного
ничего не значит для другого — такой совет был бы не догадкой, а обманом.

`npm test` прогоняет все записанные решения и убеждается, что по дороге к
победе советчик ни разу не объявил провал и ни разу не назвал верный ход
смертельным. Ложь игроку здесь — единственная по-настоящему серьёзная
поломка, поэтому её ловит отдельный сторож.

### Двое на одной клавише

Героев на карте может быть двое: `M` и `N`. Клавиши у них общие — одна стрелка,
и шаг делают оба. Кто упёрся в стену (или в напарника), тот стоит; отсюда и
берётся вся головоломка: чтобы повести одного, второго надо сначала
**припарковать**.

Отсюда же главное правило движка, на котором держатся все решения главы:

> **Очерёдность хода зафиксирована: сначала полностью ходит `M`, потом `N`.**

Правило видно на глаз. Если `M` уходит из клетки, идущий следом `N` занимает её
в тот же такт. В обратную сторону — нет: `M` ходит первым и упирается в
напарника, хотя тот в этом же такте уйдёт. Это не мелочь реализации, а рычаг,
которым игрок разводит героев там, где стены не помогают. `tools/verify-duo.js`
проверяет правило девятью очными случаями на голых картах.

Гибель любого из двоих — поражение: напарник не остаётся за старшего. Выход
требует, чтобы вышли все, причём вышедший убирается с поля и больше не мешает —
так что порядок выхода тоже задача.

Уровни главы «Вдвоём» сделаны без грунта. Причина техническая и честная: каждая
выеденная клетка удваивает пространство состояний, и точный перебор перестаёт
быть возможным. А в этой главе он нужен: длина кратчайшего решения у 141–143
найдена полным перебором, а не автопилотом.

Чего мерка резкости тут не видит: эти уровни почти не убивают (у «Двух палат»
ноль смертельных отклонений и ноль тупиковых), вся их трудность —
комбинаторная. Поэтому второй герой идёт в оценку как **объявленная** надбавка,
наравне с портами и зарядами, а не как измерение.

### Звук

Ни одного файла с записью: голос синтезируется на месте через WebAudio
(`js/sound.js`). Иначе однофайловая офлайн-сборка распухла бы на мегабайты
base64 — а она должна оставаться одним файлом, который просто открывают.

Файл делится надвое, и это не для красоты:

* `probe`/`events` — чистые функции без DOM. Они смотрят на движок до и после
  такта и говорят, **что** случилось: взял, копнул, толкнул, упало, рвануло,
  запал, порт, тяжесть, гибель, победа. Их гоняет Node;
* `Sound` — собственно **голос**: осцилляторы, шум, огибающие. Его в Node не
  проверить, и он ничего не решает.

Подряд собранные инфотроны звучат всё выше — маленькая награда за темп; пауза
в три с половиной секунды сбрасывает счёт. Выключатель помнится в `localStorage`, звук
заводится после первого касания (так требует браузер).

`node tools/verify-sound.js` проигрывает все записанные решения и требует:
«взял» прозвучало ровно столько раз, сколько собрано инфотронов; «победа» —
один раз и на последнем такте; «гибель» — ни разу; тихий такт молчит. То есть
проверяется решение о звуке, а не сам звук.

### Мерка резкости

У каждого уровня в списке стоит число от 1 до 10 — измеренная резкость.
Считает её `tools/measure.js` по записанному решению, и она складывается из
трёх разных по природе вещей:

* **измерено** — опасность (доля одиночных отклонений, после которых Мёрфи
  гибнет, если дальше идти по плану) и теснота (сколько ходов на такте вообще
  не убивают на месте); длина берётся с малым весом, потому что часть эталонных
  решений записана автопилотом, а он петляет;
* **объявлено** — односторонние порты и заряды с терминалом: там, где ход
  только в одну сторону, ошибиться порядком можно всегда;
* **выведено** — надбавка безопасному уровню, на котором буксует жадный
  автопилот: значит, он берётся расчётом, а не реакцией.

Мерка честно не видит глубины одной догадки: «Развязка» получает четвёрку,
хотя порядок обхода там единственный. Поэтому рядом с числом всегда идёт
строка «почему» — наведи на уровень в списке.

`npm test` сверяет измеренное с записанным в `levels/difficulty.json`. Мерка
детерминированная, так что расхождение означает ровно одно: уровень или
решение изменились. Тест не судит, стало лучше или хуже, — он не даёт правке
пройти молча. После осознанной правки пересчитай: `node tools/measure.js`.

На узком экране игра приближает поле и скроллит камеру за Мёрфи, а не показывает
весь уровень мелкими точками. Прогресс хранится в `localStorage`, уровни
открываются по порядку.

## Один файл

```
npm run bundle
```

Собирает всю игру (разметку, стили, скрипты, уровни) в самодостаточные файлы:

* `dist/infotron.html` — полноценная страница. Скачал, положил куда угодно,
  открыл двойным щелчком — работает офлайн, без интернета и установки.
* `dist/artifact.html` — то же самое без обёртки `<html>`, для публикации в вебе.

## Мир и его правила

| Символ | Что это | Поведение |
|---|---|---|
| `.` | грунт | Мёрфи прогрызает его насквозь |
| `#` | стена | неразрушима даже взрывом |
| `=` | чип | как стена, но взрыв её дробит |
| `O` | зонк | качается на краю, потом падает; съезжает с края опоры, толкается вбок в пустоту, давит насмерть |
| `*` | инфотрон | цель; тоже падает и скатывается |
| `E` | шлюз | открывается, когда собрано нужное число инфотронов |
| `S` | снипснак | идёт вдоль стен левой рукой, убивает при столкновении |
| `e` | электрон | идёт правой рукой; взрывается **инфотронами** |
| `o` | оранжевый диск | падает как зонк и детонирует при ударе; подрывает соседние диски |
| `^ > v <` | порт | пропускает только по стрелке, монстров не пропускает вовсе |
| `M` | Мёрфи | герой; ходит первым |
| `N` | напарник | тот же герой на тех же клавишах, но ходит вторым |

Тонкости, на которых держатся уровни:

* Если героев двое, **клавиша ведёт обоих**, и ходят они по очереди: сперва `M`,
  потом `N`. Гибель любого — поражение; выйти должны оба.

* Зонк не падает, пока под ним что-то есть — **включая самого Мёрфи**. Стоять под
  камнем безопасно; смертельно из-под него уйти и вернуться.
* Круглый предмет **съезжает с края любой твёрдой опоры** — другого камня, чипа
  и обычной стены, — если сбоку и наискось под ним пусто. С грунта не съезжает:
  грунт держит.
* Потеряв опору, зонк сначала **качается четыре тика** и только потом срывается.
  Это единственное предупреждение — и вся фора, чтобы уйти с его пути. Толкнутый
  игроком зонк падает сразу: толчок и так осознанное действие.
* Толкать зонк можно только в **пустоту**, не в грунт. Дотолкав его до дыры в полу,
  вы роняете камень — так расчищают тупики.
* Монстр ходит по периметру пустого зала и не сворачивает внутрь, пока путь свободен.
  Середина зала — безопасное место, вход и выход — нет.
* Взрыв — квадрат 3×3: он рвёт грунт, чипы, инфотроны и монстров, но не стены.
  Взрыв электрона оставляет после себя инфотроны — иногда это единственный способ
  набрать нужное количество; инфотронный взрыв перекрывает обычный, поэтому цепочка
  «зонк → диск → электрон» не съедает собственную добычу.

## Уровни

План — сто уровней, десять глав по десять; сценарий лежит в `docs/plan-100.json`
и рендерится в документ командой `npm run plan`. Готова первая глава целиком
(«Первый спуск», уровни 1–10) плюс восемь уровней из будущих глав, стоящих на
своих местах в нумерации.

Номер файла — это номер уровня, глава считается как `ceil(id / 10)`.

Уровни лежат в `levels/*.txt` обычным текстом:

```
name: Пирамида
needed: 3
hint: Зонк скатывается с круглого бока.
---
######################
#.M..................#
...
```

После правки карт нужно пересобрать `js/levels.js`:

```
npm run levels
```

## Уровни от внешней модели

Идеи можно заказывать на стороне — проверку всё равно делает движок. Два готовых промпта:

* `docs/prompt-for-level-designer.md` — **сценарий**: чертежи уровней (идея, устройство,
  порядок решения, на чём споткнётся невнимательный). Из чертежа карту собираю я.
  Просить лучше по одной главе за раз.
* `docs/prompt-for-level-author.md` — **готовые карты** в ASCII. Работает хуже: модель
  не может проверить собственную карту, поэтому часть отваливается на приёмке.

Приёмка — одной командой, и она отклоняет с причиной:

```
node tools/import-plan.js   чертежи.json --write   # проверить и подшить в план
node tools/import-levels.js карты.json    --write   # проверить карты и записать уровни
```

Чертежи проверяются на расплывчатость, нереализованные механики и норму плотности;
карты — на рваную сетку, парящие в воздухе зонки, замурованных в грунте монстров,
достижимость и, главное, на существование решения (его ищет автопилот).

## Проверка проходимости

Движок (`js/engine.js`) не знает про DOM и запускается в Node — поэтому каждый
уровень проверяется автоматически, а не «на глаз». Для каждого уровня в
`levels/solutions.json` хранится реальная последовательность ходов, которую
прогоняет тест:

```
npm test
```

Отдельно есть проверка физики — она проигрывает все эталоны и следит, чтобы
ни один предмет не «завис»: не остался на месте, когда под ним пусто и время
качания вышло.

```
node tools/audit-physics.js
```

Решения либо записаны вручную (уровни со взрывами), либо найдены автопилотом
из `tools/lib.js` — он ищет путь волной, обходит односторонние порты в последнюю
очередь и отбраковывает ходы, ведущие к смерти в ближайшие тики.

Отладка одного уровня в консоли:

```
node tools/play.js 7                       # показать стартовую карту
node tools/play.js 7 "D3 R6 r L2 .6"       # проиграть ходы (u/r/d/l — «снап», «.» — ждать)
node tools/play.js 10 --auto --trace       # прогнать автопилотом по шагам
node tools/verify.js 4 --save              # записать найденное решение в solutions.json
```

## Что где лежит

```
index.html          разметка, HUD, оверлеи
css/style.css       тёмная тема

js/levels.js        СГЕНЕРИРОВАНО из levels/*.txt
js/sprites.js       процедурные спрайты (канвас, без картинок)

```
