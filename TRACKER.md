# Бот-хаб и трекер доставок

В репозитории два способа следить за доставкой — и оба говорят, когда пора
выходить к машине, за столько минут, за сколько попросите.

```
09:05  прислали ссылку           →  «Курьер едет к получателю: ~33 мин»
09:23  осталось 15 минут         →  🔔 напоминание
09:33  осталось 5 минут          →  🔔 «Пора выходить»
09:38  курьер на месте           →  🚗
```

| | Кому подходит |
|---|---|
| **[Бот в Telegram](#бот-в-telegram)** | всем: шлёте боту ссылку, он присылает напоминания на телефон. Ничего не нужно держать открытым, компьютер не нужен вовсе |
| **[Командная строка](#командная-строка)** | если хочется положить напоминание в **Apple Напоминания или Календарь**, сделать `.ics` или разово посмотреть, где курьер |

Бот устроен как **хаб**: внутри одного бота живут независимые ветки-агенты, и
«🚕 Доставка» — первая из них. Как добавить свою — [ниже](#как-добавить-свою-ветку).

# Бот в Telegram

Один бот, внутри — ветки. Ветка выбирается кнопкой в меню (`/menu`), а если
прислать что-то узнаваемое — например ссылку на доставку — нужная ветка
откроется сама. Каждый чат помнит свою открытую ветку.

## Ветка «🚕 Доставка»

Вы кидаете боту ссылку — он ведёт карточку заказа и сам пишет, когда пора
выходить.

```
🚕 Доставка
Курьер едет к получателю: ~18 мин

📍 Сколковская улица, 7Б, подъезд 3
🚗 Халимат · LADA (ВАЗ) Granta С479СО797
🕒 Прибытие ~09:38

🔔 Напомню за: 15 мин, 5 мин
Открыть отслеживание

[ 3 мин ][ ✅ 5 мин ][ 10 мин ]
[ ✅ 15 мин ][ 30 мин ]
[ ⏱ Свой интервал ]
[ ⏹ Не следить ]
```

- **Карточка обновляется сама**, пока курьер едет: время прибытия меняется
  прямо в ней, лишних сообщений в чате не появляется.
- **Напоминание приходит отдельным сообщением** — именно оно даёт push
  на телефон.
- **Интервал выбираете кнопками**, их можно включить несколько сразу:
  например за 15 и за 5 минут. Нужного значения нет — «⏱ Свой интервал»
  и число в ответ.
- Выбранные интервалы бот **запоминает** и в следующий раз поставит сам.
- В одном сообщении можно прислать сразу несколько ссылок.

Команды: `/start` — с чего начать, `/menu` — выбрать ветку,
`/help` — справка по открытой ветке, `/list` — что сейчас отслеживается.

## Как поднять

**1. Создать бота.** Откройте [@BotFather](https://t.me/BotFather) → `/newbot`,
придумайте имя и адрес, скопируйте токен.

> Нужен **отдельный** бот, не тот, что рассылает напоминания сотрудникам:
> два процесса с одним токеном будут мешать друг другу, и Telegram начнёт
> рвать соединение. Бот проверяет это при старте и скажет прямым текстом.

**2. Прописать в `.env`:**

```bash
HUB_BOT_TOKEN=123456789:AAExample...
HUB_ALLOWED_IDS=123456789   # ваш Telegram ID (@userinfobot); пусто — бот открыт всем
HUB_TZ=Europe/Moscow        # в этом поясе показывается время
```

**3. Запустить:**

```bash
make install     # если окружение ещё не создано
make bot
```

Дальше — просто пришлите боту ссылку.

## На сервере

Если бот напоминаний уже стоит по инструкции из [README](README.md), хаб
добавляется рядом двумя командами:

```bash
cd ~/reminder-bot-src && git pull
sudo bash deploy/install-hub.sh
```

Скрипт спросит токен нового бота и ваш Telegram ID, проверит токен у Telegram,
скопирует код, настроит автозапуск и покажет, что получилось. Бот напоминаний,
его базу и настройки он не трогает; повторный запуск безопасен — им же
обновляются на свежую версию.

Порты открывать не нужно: бот сам ходит в Telegram (long polling).

| Задача | Команда |
|---|---|
| Состояние | `sudo systemctl status hub-bot` |
| Логи вживую | `sudo journalctl -u hub-bot -f` |
| Перезапуск | `sudo systemctl restart hub-bot` |
| Обновить | `cd ~/reminder-bot-src && git pull && sudo bash deploy/install-hub.sh` |
| Выключить | `sudo systemctl disable --now hub-bot` |

# Командная строка

```bash
python3 -m tracker add https://dostavka.yandex.ru/route/e90be707-... \
        --alert 5 --notify reminders --watch
```

Одна строка делает всё: берёт ссылку в работу, кладёт напоминание в Apple
Напоминания за 5 минут до прибытия и начинает следить за изменениями ETA.

Проверить, где курьер, не заводя отслеживания:

```bash
python3 -m tracker status https://dostavka.yandex.ru/route/e90be707-...
```

```
Курьер едет к получателю:  ~8 мин
белый LADA (ВАЗ) Granta • нужно выйти к машине курьера, когда он будет на месте
Адрес: Сколковская улица, 7Б, подъезд 3
Курьер: Халимат · LADA (ВАЗ) Granta С479СО797
Осталось: 8 мин (примерно к 09:38)
```

## За сколько минут напоминать

Интервал выбираете вы, порогов может быть несколько:

```bash
--alert 5                 # за 5 минут
--alert 15 --alert 5      # два напоминания
--alert 30,10,3           # то же самое через запятую
--alert 0                 # только когда курьер уже на месте
```

Если подключиться, когда ехать осталось 3 минуты, трекер не станет сыпать
«за 15» и «за 5» разом — сработает только ближайший порог, один раз.

## Способы напоминания (`--notify`)

| Значение | Что делает | Нужен запущенный трекер? |
|---|---|---|
| `reminders` | запись в **Apple Напоминаниях** с будильником | нет |
| `calendar` | событие в **Apple Календаре** с будильниками | нет |
| `ics` | файл `.ics` с будильниками — для iPhone и любых календарей | нет |
| `banner` | баннер macOS | да |
| `telegram` | сообщение в Telegram | да |
| `console` | строка в терминале | да |

Можно комбинировать: `--notify reminders,telegram`.

**`reminders` и `calendar`** работают через `osascript`, то есть только на
macOS. При первом запуске macOS спросит разрешение на доступ к Напоминаниям
и Календарю — его нужно выдать. Если они синхронизируются с iCloud, сигнал
прозвучит и на iPhone. Пока курьер едет, запись переносится вслед за
меняющимся временем прибытия.

**`ics`** — запасной путь, когда Мака нет. Файл кладётся в `data/ics/`; откройте
его на iPhone (из почты, Телеграма, iCloud Drive) — событие с будильниками
добавится в Календарь. Разово файл можно сделать так:

```bash
python3 -m tracker ics https://dostavka.yandex.ru/route/... --alert 10 -o ~/Desktop/delivery.ics
```

**`telegram`** — разовая отправка из командной строки, без бота и кнопок.
Берёт токен и адресата из `HUB_BOT_TOKEN` (или `BOT_TOKEN`) и
`TRACKER_CHAT_ID` (или первого из `ADMIN_IDS`). Если нужен полноценный
диалог с карточкой и кнопками — это [бот](#бот-в-telegram).

## Команды

| Команда | Что делает |
|---|---|
| `add <ссылка>` | взять поездку в отслеживание (`--alert`, `--notify`, `--label`, `--watch`) |
| `watch` | следить за всеми добавленными поездками (`--once` — один проход) |
| `status <ссылка>` | разово показать, где курьер |
| `list` | показать отслеживаемые поездки |
| `remove <id или ссылка>` | убрать поездку и её запланированные напоминания |
| `prune` | почистить завершённые |
| `ics <ссылка>` | сделать файл календаря с будильниками |

## Чтобы не запускать вручную (macOS)

`~/Library/LaunchAgents/ru.tracker.watch.plist`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>            <string>ru.tracker.watch</string>
  <key>ProgramArguments</key>
  <array>
    <string>/usr/bin/python3</string>
    <string>-m</string><string>tracker</string>
    <string>watch</string>
  </array>
  <key>WorkingDirectory</key> <string>/Users/ВЫ/Main</string>
  <key>RunAtLoad</key>        <true/>
  <key>KeepAlive</key>        <true/>
</dict>
</plist>
```

```bash
launchctl load ~/Library/LaunchAgents/ru.tracker.watch.plist
```

Тогда достаточно `add`, а слежение подхватится само.

**Хаб**

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `HUB_BOT_TOKEN` | — | токен **отдельного** бота от @BotFather; обязателен |
| `HUB_ALLOWED_IDS` | пусто | кому можно пользоваться ботом; пусто — всем |
| `HUB_TZ` | `DEFAULT_TZ` или `Europe/Moscow` | в каком поясе показывать время |
| `HUB_STATE` | `data/hub.json` | какая ветка открыта в каком чате |

Старые имена `TRACKER_BOT_TOKEN`, `TRACKER_ALLOWED_IDS` и `TRACKER_TZ` тоже
работают — переименовывать уже прописанное не нужно.

**Ветка «Доставка» и командная строка**

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `TRACKER_POLL_SECONDS` | `10` | как часто опрашивать Яндекс (минимум 5) |
| `TRACKER_ALERTS` | `5` | интервалы напоминаний по умолчанию |
| `TRACKER_NOTIFIERS` | `console` | способы уведомления по умолчанию для командной строки |
| `TRACKER_STATE` | `data/trips.json` | файл со списком поездок |
| `TRACKER_ICS_DIR` | `data/ics` | куда складывать `.ics` |
| `TRACKER_REMINDERS_LIST` | список по умолчанию | в какой список класть напоминания |
| `TRACKER_CALENDAR` | первый доступный | в какой календарь класть события |
| `TRACKER_CHAT_ID` | первый из `ADMIN_IDS` | кому слать при `--notify telegram` |

## Как это устроено

Страница `dostavka.yandex.ru/route/<id>` — обычное одностраничное приложение;
данные она берёт из открытого, не требующего авторизации метода:

```
POST https://ya-authproxy.taxi.yandex.ru/4.0/cargo-c2c/v1/shared-route/info
{"key": "<id из ссылки>"}
```

Трекер обращается туда же. Заголовок ответа `x-refresh-after` подсказывает,
как часто опрашивать; когда до ближайшего порога остаётся меньше двух минут,
период сокращается до 10 секунд, чтобы не проспать напоминание.

**Отдельного числового поля с ETA в ответе нет** — время прибытия приходит
текстом («Курьер едет к получателю: ~33 мин»), поэтому его разбирает
[`tracker/eta.py`](tracker/eta.py): часы и минуты, диапазоны («10–15 мин» —
берём раннюю границу, лучше выйти раньше), английские формулировки.

```
tracker/                 движок, зависимостей нет — только стандартная библиотека
├── cli.py               разбор команд
├── watcher.py           цикл опроса и решение «пора напоминать»
├── providers.py         запросы к API Яндекса и разбор ответа
├── eta.py               «~1 ч 5 мин» -> минуты
├── models.py            поездка, её состояние, событие
├── store.py             список поездок в JSON
└── notifiers/           напоминания, календарь, .ics, Telegram, баннер, консоль

hub/                     бот в Telegram: каркас и ветки
├── main.py              сборка бота, подключение веток, запуск
├── registry.py          что такое ветка (Agent) и что она приносит с собой
├── router.py            приветствие, меню веток, переключение
├── middlewares.py       доступ к боту и выбор ветки для сообщения
├── filters.py           «эта ветка сейчас открыта»
├── state.py             какая ветка открыта в каком чате
├── config.py            токен, доступ, часовой пояс
└── agents/
    ├── __init__.py      список подключённых веток
    └── taxi/            ветка «🚕 Доставка»
        ├── __init__.py  описание ветки: имя, приветствие, зависимости
        ├── handlers.py  ссылка, кнопки интервалов, /list
        ├── poller.py    фоновый опрос: обновить карточку, прислать напоминание
        ├── service.py   отправка и обновление карточки, переключение порогов
        ├── keyboards.py кнопки под карточкой
        ├── texts.py     тексты ветки
        ├── callbacks.py фабрики callback_data
        └── config.py    настройки ветки
```

**Ключевые решения**

- **Ветки ничего не знают друг о друге.** Хаб держит для каждого чата открытую
  ветку и отдаёт ей обычные сообщения; всё остальное — роутер, хранилище,
  фоновая задача — у ветки своё. Добавить вторую можно, не трогая первую.
- **Кнопки не фильтруются по активной ветке, сообщения — фильтруются.**
  У каждой ветки свой префикс `callback_data`, поэтому кнопка старой карточки
  работает даже после переключения. А вот обычный текст достаётся только
  открытой ветке — иначе две ветки отвечали бы на одно сообщение.
- **Узнаваемый текст открывает свою ветку сам**, но не посреди диалога:
  если ветка ждёт ответа, перехватывать нельзя. Команды по этому правилу
  не перехватываются никогда.
- **Логика напоминаний одна на всех.** `evaluate()` — чистая функция: получает
  поездку и её состояние, возвращает список событий. Ею одинаково пользуются
  цикл в терминале и бот, поэтому поведение не расходится.
- **Прибытие считается от момента опроса**, а не от «сколько было минут в
  прошлый раз»: между опросами время идёт, и порог «за 5 минут» не съезжает.
- **Карточка редактируется, напоминание присылается.** Обновление ETA не должно
  сыпать сообщениями, а напоминание обязано дать push — поэтому карточка
  правится на месте, а событие уходит новым сообщением.
- **Порог помечается отработанным сразу после отправки**, до обновления
  карточки: сбой на редактировании не должен задваивать напоминание.
- **Включение уже прошедшего порога не стреляет задним числом.** Поставили «за
  15 минут», когда ехать осталось 3, — бот скажет, что момент прошёл, а не
  пришлёт напоминание немедленно.
- **Запланированные напоминания переносятся**, если ETA изменился больше чем
  на минуту. Мелкие колебания игнорируются, чтобы не дёргать Напоминания
  каждые 10 секунд.
- **Сетевой сбой не теряет поездку**: запрос повторяется трижды, поездка
  остаётся в списке. А вот блокировка бота снимает поездку — писать больше
  некому.
- **Значения в AppleScript передаются аргументами** (`on run argv`), а не
  склейкой строк, — апострофы и кавычки в адресах ничего не ломают.

## Как добавить свою ветку

Ветка — это папка в `hub/agents/` и один объект `Agent`. Хаб сам подхватит
её роутер, зависимости и фоновую задачу и покажет в меню.

`hub/agents/weather/__init__.py`:

```python
from aiogram import F, Router
from aiogram.types import BotCommand, Message

from ...registry import Agent

router = Router(name="agent-weather")


@router.message(F.text)
async def any_text(message: Message, weather_client) -> None:
    await message.answer(await weather_client.forecast(message.text))


def setup(data, hub_config):
    """Зависимости ветки. Имена — с приставкой, чтобы ветки не мешали друг другу."""
    data["weather_client"] = WeatherClient(tz=hub_config.tz)


agent = Agent(
    slug="weather",
    title="🌦 Погода",
    summary="рассказываю прогноз по городу",
    greeting="Назовите город — пришлю прогноз.",
    router=router,
    commands=[BotCommand(command="forecast", description="Прогноз на неделю")],
    claims=lambda text: text.lower().startswith("погода"),
    setup=setup,
)
```

И одна строка в `hub/agents/__init__.py`:

```python
AGENTS: list[Agent] = [taxi_agent, weather_agent]
```

Что даёт каждое поле:

| Поле | Зачем |
|---|---|
| `slug` | идентификатор: он же в кнопке меню и в файле состояния |
| `title`, `summary` | как ветка выглядит в меню и в приветствии |
| `greeting` | что показать при входе в ветку; это же отдаёт `/help` |
| `router` | обработчики; **обычные сообщения** приходят, только когда ветка открыта |
| `commands` | команды ветки в меню Telegram; работают тоже только в своей ветке |
| `claims` | «это моё?» — если текст узнан, хаб откроет ветку сам |
| `setup` | положить зависимости в данные диспетчера (клиенты, хранилища, настройки) |
| `background` | фоновая задача: объект с `start()` и `async shutdown()` |

Правила, о которых стоит знать:

- **Зависимости именуйте с приставкой** (`taxi_store`, `weather_client`):
  диспетчер подставляет их в обработчики по имени параметра, общее на всех
  пространство имён.
- **Свой префикс `callback_data`** (`CallbackData, prefix="weather"`).
  Нажатия на кнопки не фильтруются по активной ветке — кнопка старой карточки
  должна работать всегда, даже если человек уже ушёл в другую ветку.
- **`claims` не перебивает диалог.** Если ветка ждёт ответа (выставлено
  FSM-состояние), сообщение достанется ей, а не той, которая «узнала» текст.
  Команды (`/что-то`) тоже никогда не перехватываются по `claims`.
- **Ветки не знают друг о друге.** Общее у них только то, что положил хаб:
  токен, доступ, часовой пояс.

## Ограничения

- Ссылка живёт, пока живёт заказ: когда Яндекс закрывает поездку, метод
  начинает отвечать ошибкой. Трекер в этот момент помечает поездку
  завершённой и убирает свои запланированные напоминания.
- Время прибытия — оценка Яндекса. Трекер её не улучшает, только следит.
- Это неофициальный метод: если Яндекс поменяет формат ответа, чинить нужно
  будет `tracker/providers.py` и `tracker/eta.py`. Всё остальное от формата
  не зависит.
- `reminders`, `calendar` и `banner` требуют macOS. На Linux и Windows
  остаются бот, `ics`, `telegram` и `console`.
- Бот по умолчанию открыт всем, кто его найдёт (следить он будет только за
  теми ссылками, которые ему прислали). Закрывается `HUB_ALLOWED_IDS`.

Сеть в тестах не используется: ответы Яндекса подставляются фикстурами,
Telegram — подставной сессией, которая ловит вызовы API. Проверяется в том
числе, что напоминание уходит ровно один раз, что карточка обновляется без
новых сообщений и что заблокировавшему бота пользователю писать перестают.

Каркас хаба проверяется на двух ненастоящих ветках-заглушках: что сообщение
достаётся открытой ветке и только ей, что узнаваемый текст открывает свою
ветку сам, что диалог одной ветки нельзя перебить другой и что разные чаты
живут в разных ветках независимо.
